## 原题

根据 `strokes`（实际杆数）与 `par`（标准杆数）的差距，返回对应名称：

| Strokes | Return |
|---|---|
| 1 | "Hole-in-one!" |
| <= par - 2 | "Eagle" |
| par - 1 | "Birdie" |
| par | "Par" |
| par + 1 | "Bogey" |
| par + 2 | "Double Bogey" |
| >= par + 3 | "Go Home!" |

---

## Matt 的第一次答案（❌ 5 类错误）

```js
function golfScore(par, strokes) {
  if (strokes = 1) {                          // ← 少了两个 =
    return "Hole-in-one!";
  } else if (strokes<= par - 2 ) {
    return "Eagle";
  } else if (strokes =par - 1) {              // ← 少了两个 =
    return "Birdie";
  } else if (par=strokes &&par!=1) {          // ← 少了两个 = + 多余条件
    return "Par";
    else return "Hole-in-one!";               // ← if 块没关就写 else
  } else if (strokes =par + 1) {
    return "Bogey";
  } else if (strokes=par + 2) {
    return "Double Bogey";
  } else (strokes >= par + 3 ) {              // ← else 不能带条件
    return "Go Home!";
  }
  return "Change Me";
}
```

## 错误分类

### 🔴 A 类｜语法错误（文件跑不起来）

**① 第 12-13 行：`if` 块没关就写 `else`**

    return "Par";
    else return "Hole-in-one!";      ← 这里缺 }

原因：`return` 让人以为"结束了"。但 **`return` 结束函数，不结束 `if` 块**。

**② 第 18 行：`else` 带了条件**

    } else (strokes >= par + 3 ) {

实跑报错 `SyntaxError: Unexpected token '{'`——引擎看到 `else`，等的是 `{`，结果等到了 `(`。

### 🟡 B 类｜概念错误（致命）

**③ `=` 当成 `===` 用了 5 次**（第 5、9、11、14、16 行）

**实跑证明后果：**

    function testAssign(strokes) { if (strokes = 1) { return "条件成立了"; } }
    testAssign(99)  →  "条件成立了"      ← 传 99 进去也成立！

**`strokes = 1` 干的三件事：**
1. 把 `1` 塞给 `strokes`（把原值覆盖掉）
2. **整个表达式的值就是 `1`**
3. `1` 是**真值** → 条件永远成立

**结果：第一个分支永远成立，后面 6 个 `else if` 全部走不到。**

**④ 第 11 行多了 `&&par!=1`** —— 题目没有这条规则。加条件靠想象，不是靠题目。

### 🟢 C 类｜逻辑错误

**⑤ 第 13 行 `else return "Hole-in-one!"`** —— 就算语法修好，它挂在 Par 的 else 里，会吃掉后面所有分支。

## 正确写法（实跑 8/8 通过）

```js
function golfScore(par, strokes) {
  if (strokes === 1) {
    return "Hole-in-one!";
  } else if (strokes <= par - 2) {
    return "Eagle";
  } else if (strokes === par - 1) {
    return "Birdie";
  } else if (strokes === par) {
    return "Par";
  } else if (strokes === par + 1) {
    return "Bogey";
  } else if (strokes === par + 2) {
    return "Double Bogey";
  } else {
    return "Go Home!";
  }
}
```

## 三个知识点（按重要性排）

### 🎯 1. `=` vs `==` vs `===` ★★★★

    =     赋值      把右边塞给左边
    ==    相等      会做类型转换（"5" == 5 是 true）
    ===   严格相等   值和类型都要一样（"5" === 5 是 false）

**一条铁律**：

> **`if (...)` 括号里看到单个 `=` → 100% 是错的。比较一律用 `===`。**

**为什么最重要**：
- JS 最经典的 bug 来源，没有之一
- **不报错**——只悄悄让条件永远成立
- **还会改掉变量的值**，破坏后面所有逻辑
- 以后写 Solidity 时，权限检查写错一个等号是**资金被盗**级别的 bug

### 🎯 2. `else if` vs `else`

    else if (条件) { }     ← 有条件
    else { }               ← 没条件，意思是"以上都不是"

**最后一个分支直接 `else` 就够**，不用把条件再写一遍。好处：题目的规则漏了某种情况时，`else` 能兜住。

### 🎯 3. `return` 不结束花括号

    if (A) {
      return "x";
      else { }        ← ❌ 报错：if 块没关
    }

**`return` 管执行流，`}` 管语法结构。两件事。**

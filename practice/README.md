# practice —— 练习与难点库

这个目录记录 Matt 的学习痕迹，服务于两件事：

1. **闸门 A（动手）**：有可验证的代码产出，而不是"我学过"
2. **闸门 C（回溯）**：积累难点，定期抽题重做，对抗遗忘

---

```
practice/

    ├── R001.md
```

## 一、basic-js/ —— 练习代码

**频率**：每 2–3 天提交一次（P1 阶段。前 20 节练习太简单，不为了提交而提交）

**做法**：

1. 在 freeCodeCamp 做完当天的挑战
2. 把代码粘贴到 `basic-js/D<序号>.js`
3. 文件开头三行写清楚：

```js
// D001  2026-10-14 ｜ fCC 基础 JavaScript 1-8
// 卡点：无
// 备注：可选

// 1. 给代码添加注释
// 这是单行注释

/* 这是
   多行注释 */

// 2. 声明变量
var myName;
```

4. 提交：

```bash
git add .
git commit -m "D001: Basic JS 1-8"
git push
```

**命名**：`D001` = 第 1 次提交，不是日期。跨模块时换文件夹（`practice/python/`、`practice/solidity/`）。

## 二、review/ —— 难点库（核心）

### 录入流程

```
Matt 遇到觉得难的题
      ↓ 拍照发给我
AI 转录成 R<编号>.md
      ↓
在 index.md 登记（含首次复习日期）
```

**只记"你觉得有难度"的**。一眼就会的不用发——难点库的价值在于稀疏，不在于全。

### 复习机制（对接闸门 C「每 3 天回做 1 道 ≥3 天前的题」）

| 复习结果 | 下次间隔 |
|---|---|
| 做对 | **×2**（3 → 6 → 12 → 24 天） |
| 做错 | **回到 3 天** |
| 连续 3 次做对 | 标记 `已掌握`，移出常规轮换 |

AI 每 3 天从未到期的条目里抽 1–2 题，让 Matt 重做，然后更新 `index.md`。

### 单条格式

```markdown
# R001 ｜ 2026-10-15 ｜ Basic JavaScript

- 来源：freeCodeCamp 基础 JavaScript · 第 41 题「通过索引访问数组中的数据」
- 难度：★★☆
- 标签：数组 / 索引

## 原题（转录）

## 我第一次的答案

## 卡在哪

## 复习记录

| 日期 | 结果 | 下次 |
|---|---|---|
| 2026-10-18 | 做对 | 2026-10-24 |
```

## 三、为什么这么做

- **闸门 A 需要硬证据**：AI 能直接查 `git log`，不靠记忆和自述
- **提交记录会累积**：91 天后 GitHub 主页是一片连续的提交记录，面试官会看
- **可回溯**：三个月后想查"我当初怎么理解闭包的"，翻文件就行，不用重看全部课程
- **对抗遗忘**：难点库 + 间隔复习，比"学一遍就过"有效得多
